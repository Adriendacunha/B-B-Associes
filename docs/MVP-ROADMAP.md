# 39 Collect by Codex - roadmap MVP

## Objectif MVP

Permettre a des clients particuliers de transmettre leurs documents fiscaux via une checklist simple, avec suivi cabinet, verification humaine et reduction mesurable des allers-retours.

## Lots prioritaires

### Lot 1 - Cadrage produit

- Confirmer le perimetre exact des profils clients inclus dans le beta-test.
- Confirmer les documents fiscaux prioritaires.
- Valider le nom public ou interne `39 Collect by Codex`.
- Decider si le depot GitHub doit etre renomme.

### Lot 2 - Experience client

- Simplifier le parcours de depot documentaire.
- Clarifier les statuts de piece : attendu, depose, incomplet, valide, refuse.
- Reduire les messages techniques visibles par le client.
- Tester le parcours avec un petit panel beta.

### Lot 3 - Back-office cabinet

- Prioriser la file de validation humaine.
- Donner une vision claire des dossiers incomplets.
- Faciliter les relances ciblees.
- Mesurer le temps gagne par dossier.

### Lot 4 - Securite, LPD et donnees fiscales

- Confirmer l'hebergement cible et la localisation des donnees.
- Valider la duree de conservation des fichiers et donnees applicatives.
- Confirmer les droits d'acces internes.
- Clarifier les conditions d'utilisation de l'IA sur documents fiscaux.

### Lot 5 - Integrations

- Confirmer le tenant Microsoft 365 et le stockage OneDrive cible.
- Valider la boite d'envoi des relances.
- Tester le depot automatique dans l'arborescence cabinet.
- Prevoir le mode degrade si Graph ou l'IA ne repond pas.

## Definition de pret pour une issue MVP

Une issue peut entrer en implementation si :

- le besoin utilisateur est formule en une phrase ;
- le resultat attendu est verifiable ;
- les donnees personnelles traitees sont identifiees ;
- l'impact sur le MVP est clair ;
- les dependances bloquantes sont explicites.

## Definition de termine

Une issue MVP est terminee si :

- le comportement est implemente ou la decision est documentee ;
- les tests pertinents ont ete executes ;
- les impacts LPD/securite ont ete consideres ;
- la documentation utile est mise a jour ;
- les points restants sont transformes en issues ou questions ouvertes.
